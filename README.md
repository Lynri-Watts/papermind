# PaperMind — 你的 AI 科研副驾驶

**发现文献、精读论文、与 AI 有据可查地讨论——所有引用都能一键回到原文核实。**

PaperMind 是一个运行在你自己电脑上的全栈应用。它把「检索 → 精读 → 追问 → 收藏整理」
连成一条不中断的研究流水线，并且坚持一条底线：

> **AI 不是答案的自动售货机，而是探索的副驾驶。**
> 它说的每一句话都必须绑定真实出处；没有依据，就明确说"没有材料"，而不是编造。

## 1. 它能为你做什么

做研究的人普遍有三个痛点，PaperMind 逐一回应：

| 痛点 | PaperMind 的回答 |
|---|---|
| **信息过载**：每年数百万篇新论文，追不过来 | 四个学术数据源一键聚合检索，按字段精确筛选，结果如实标注来自哪个源；知识图谱帮你看清论文、作者、主题之间的关系 |
| **AI 幻觉**：通用大模型会编造不存在的文献 | 回答中每一处事实都带句内引用 `[Source N]`，点击即跳转到 PDF **原句所在段落并高亮**；AI 读不到全文就不会假装读过 |
| **工具割裂**：搜索、阅读、笔记、问答分散在各处 | 探索、阅读器、右侧 AI 助手在同一应用内协同；你的上下文库、打开的标签、对话记录在重启后原样恢复 |

## 2. 一分钟理解典型工作流

```
 ┌─────────┐   打开/收藏    ┌─────────┐   选中提问/自由追问   ┌──────────────┐
 │  探索    │ ────────────▶ │  研究    │ ──────────────────▶ │   AI 助手     │
 │ 多源检索 │               │ 精读 PDF │ ◀──── 引用跳回原句 ─ │ 带出处的回答  │
 └─────────┘               └─────────┘                      └──────────────┘
      │                         │                              │
      └────── 加入上下文库 ◀─────┴──────── 网页/摘录也可收藏 ────┘
                          （按工作区隔离，重启不丢失）
```

1. 在**探索**页用标题、作者、关键词等字段检索，点开抽屉看详情；
2. 在**研究**页多标签精读，选中任意文字直接提问、翻译、总结；
3. AI 助手给出的答案附 `[Source N]`，点击即可回到 PDF 对应段落核实；
4. 重要论文与网页收入**上下文库**，成为后续所有提问的专属素材；
5. 关掉应用，明天再打开——标签、对话、收藏、搜索状态都还在原处。

## 3. 功能导览

### 3.1 主页：工作区（你的项目容器）

- **工作区是文献与文件的受控容器**：每个研究课题建一个工作区，它拥有独立的上下文库、
  阅读标签与上传文件，互不串扰。
- 可以创建、选定、删除工作区，并查看其中的文件概览；点击卡片即**选定**该工作区，
  卡片上的按钮会变为不可点击的「已选定」，清晰标识当前所在项目。
- 应用启动默认进入主页；上次的浏览状态会按工作区分别记住。

> 说明：**工作区**与侧边栏的「创作」是两个概念。工作区是容器（始终可用）；
> 「创作」是其下的 LaTeX 写作页面，目前处于维护中（见 [3.5](#35-创作维护中暂不可用)）。

### 3.2 探索：发现文献，看清领域结构

- **四个数据源聚合**：Semantic Scholar、OpenAlex、arXiv、CORE 并发检索，
  自动去重、交叉输出，每条结果都标明真实来源与该源的命中/失败情况（如匿名限流）。
- **字段化高级检索**：标题 / 摘要 / 关键词 / 作者 / 全文 / 年份区间任意组合；支持加载更多。
- **来源筛选**：搜索栏可只查指定数据源；下拉里只出现你在设置中启用的源。
- **详情抽屉**：点击论文从右侧浮出详情面板，不挤占主界面；可直接在阅读器打开或收入上下文库。
- **知识图谱**：画布中央以论文、主题、作者三类节点可视化你积累的文献关系，支持缩放、平移与点击。

### 3.3 研究：纯净的论文阅读器

- **纯阅读界面**：没有搜索框干扰；多篇论文以标签页同时打开（远程论文与本地 PDF 一视同仁）。
- **上传文献**：通过「上传文献」把本地 PDF 放进当前工作区，之后检索问答、引用定位等全部能力对它同样生效。
- **高性能 PDF 渲染**：只渲染视口附近的页面并回收离屏页，大文件也省内存；翻页预取、滚动流畅。
- **选中即操作**：划选任意文字，可直接向 AI 提问、翻译、总结、提炼要点。
- **一键加入上下文**：元数据栏的书签按钮把当前论文收进当前工作区的上下文库；
  已收录时显示「已在上下文」，避免重复操作。
- **打不开的论文怎么办（防限流设计）**：
  打开论文或加入上下文时，系统会**自动尝试一次**获取全文；若失败（如数据源限流、无开放 PDF），
  界面明确标记「无法打开」并显示原因，**此后不会再自动重试**——你可以在阅读器失败面板或
  上下文库卡片上点击**刷新按钮**手动重试。这是为了避免反复请求把数据源额度打光。

### 3.4 AI 助手：贯穿所有页面的右侧面板

助手面板在主页、探索、研究页都可呼出（可收起、可拖拽调宽），包含对话与上下文库两部分。

**可溯源的问答**

- AI 采用「思考 → 调用工具 → 观察 → 再思考 → 回答」的工作方式：需要文献时会**自主检索**，
  需要全文时会**自主通读**，全过程以步骤卡片实时呈现并留存记录，随时可停止生成。
- 回答中的事实以句内 `[Source N]` 标注，底部附出处卡片（区分「当前论文」与「上下文条目」）；
- 点击引用直接跳转 PDF **原句段落并高亮**，跨页也能定位；
- 引用必须是论文中的**逐字完整句子**，不允许改写或截断；
- 支持多轮追问，AI 记得最近的对话上下文，但全文永远不会被塞进历史（节省你的 token）。

**上下文库：你的专属素材集**

- 收藏**论文**：带 AI 摘要与标签，按工作区隔离；
- 收藏**网页**：助手面板的地球图标按钮直接添加外部链接，自动抓取正文并生成摘要；
- **PDF 选中摘录**：阅读器中划选的文字可作为多条摘录保存（同一篇论文可保存多段）；
- 当前正在读的论文在每次提问前会被**自动、幂等**地收入库中，保证问答能读到它的全文；
- 无法打开全文的论文会带红色「无法打开」标记与手动刷新按钮；
- 每篇库中论文都可通过书本图标**一键转移到阅读器**打开；
- 每条条目可查看全文、编辑摘要、刷新、删除。

### 3.5 创作（维护中，暂不可用）

侧边栏的「创作」是 LaTeX 写作与预览模块（三栏：阅读助手 / 编辑器 / 实时预览）。
因功能尚在打磨，当前入口显示为灰色「维护中」，暂时无法进入；工作区的文件管理与文献阅读不受影响。

### 3.6 设置：服务、数据源与界面语言

- **大模型服务**：填入任意 OpenAI 兼容服务的地址、密钥与模型名（OpenAI、DeepSeek、智谱、Moonshot 等）。
  密钥只保存在**后端本地配置文件**中，界面只显示掩码，永远不回显、不进前端、不进仓库。
- **数据源管理**：查看四个源的凭据状态、填写你自己的 key/邮箱以提升限流额度、
  启用/停用、拖拽调整聚合优先级；每个源与模型服务都有**连通性测试**，如实回显成功、耗时或失败原因。
- 设置保存后热加载生效，无需重启服务。
- **界面语言**：支持中文 / English 切换，默认跟随浏览器语言；前后端提示文案均已本地化。

## 4. 核心理念

PaperMind 的每个功能取舍都来自以下原则，理解它们有助于你预判软件的行为：

1. **可溯源，不幻觉**。没有读到的材料不引用；引用必为原句；每条引用可点击核实。
   AI 判断"没有可用材料"时会直接说明，而不是勉强作答。
2. **AI 负责编排，工具负责执行**。何时检索、检索什么、要不要读全文，由模型根据问题自主决定，
   而不是写死的流程——所以你会看到它先搜索、再挑几篇读、最后综合回答。
3. **为你的额度和 token 负责**。论文全文不随每个问题上传，AI 只在需要时按 ID 读取；
   网络获取自动只尝试一次，重试权留给你，避免触发数据源限流。
4. **状态不丢失**。打开的标签、搜索词与结果、对话与出处、收藏与摘录、当前所在工作区，
   全部持久化，重启后恢复到离开时的样子。
5. **项目彼此隔离**。不同课题的文献与文件分工作区存放，以 `default` 之外的独立身份保存状态。
6. **隐私与数据自主**。密钥只存在本机后端；文献库存放在本地数据库与工作区文件夹，
   不依赖任何第三方云账号。
7. **克制的界面**。阅读器只做阅读；复杂详情用浮层抽屉；面板宽度可拖拽，不让固定控件挤占正文。

## 5. 安装与启动

PaperMind 在本地运行，分为后端与前端两部分。

### 环境要求

| 组件 | 要求 |
|---|---|
| 后端 | Python 3.11+（建议使用 conda 虚拟环境） |
| 前端 | Node.js ≥ 18.20（建议 20+）与 npm |

### 第一步：启动后端

在 `backend/` 目录下：

```bash
# 1)（建议）创建并激活虚拟环境，例如：
conda create -n papermind python=3.11
conda activate papermind

# 2) 安装依赖
pip install -r requirements.txt

# 3) 准备配置文件
#    Windows: copy .env.example .env
#    macOS/Linux: cp .env.example .env
#    然后至少填写 LLM_BASE_URL / LLM_API_KEY / LLM_MODEL

# 4) 启动（默认监听 http://127.0.0.1:5001）
python app.py
```

### 第二步：启动前端

在仓库根目录另开一个终端：

```bash
npm install
npm run dev
```

浏览器打开终端中提示的地址（默认为 http://localhost:5173 ）即可使用。
数据源 key、启用状态与优先级也可以稍后在应用内**设置页**填写，保存后立即生效。

## 6. 常见问题

**Q：必须配置 API key 才能用吗？**
LLM 服务的地址、密钥与模型名是必填的（否则无法问答），支持任何 OpenAI 兼容接口。
数据源 key 全部可选：不填时 Semantic Scholar / CORE 以匿名方式工作（限流较严），
arXiv 与 OpenAlex 无需 key（OpenAlex 填邮箱可提升额度）。

**Q：AI 回答"没有可用于回答的材料"是什么意思？**
说明在当前论文、你的上下文库以及实时检索结果中都没找到依据。可以先打开相关论文、
把论文或网页加入上下文库，或把问题描述得更具体后再问。

**Q：某篇论文显示"无法打开"？**
该论文可能没有开放 PDF，或数据源临时限流。系统已自动尝试过一次，不会反复请求；
请稍后在阅读器失败面板或上下文库卡片上点击**刷新按钮**手动重试。

**Q：点击 `[Source N]` 没有反应或定位不准？**
定位基于全文句子的模糊匹配，个别扫描版 PDF 或排版特殊的页面可能不命中，属于已知边界；
出处卡片本身仍可展开查看被引用的完整段落。

**Q：如何切换中英文？**
侧边栏 → 设置 → 界面语言。切换后界面与后端提示立即变为对应语言，默认首次使用时跟随浏览器。

**Q：创作模块去哪了？**
LaTeX 写作功能正在维护，入口暂时置灰。工作区管理、文献阅读、检索与问答均可正常使用。

**Q：浏览器扩展是什么？**
`extension/` 目录内有一个 Chrome 扩展（Manifest V3）的**早期原型**，可在
`chrome://extensions` 开发者模式下加载；它目前仅在浏览器本地保存高亮笔记，尚未与主应用打通。

## 7. 数据保存在哪里

所有数据都在你本机，无需注册任何云账号：

- **数据库**：`backend/data/papermind.db`（论文元数据、摘要、上下文库、对话状态、界面快照等）；
- **PDF 缓存**：`backend/data/pdfs/`（下载过的原文，重复打开不重复下载）；
- **工作区文件**：`backend/data/workspaces/<工作区id>/`（你上传的 PDF 与其他文件）；
- **密钥配置**：`backend/.env`（仅此一处，请不要分享或提交它）。

三级全文获取策略：优先读本地数据库 → 其次解析磁盘上的 PDF → 最后才联网下载，
既保护网络额度，也让离线时仍能阅读已缓存的论文。
